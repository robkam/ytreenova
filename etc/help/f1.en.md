# YtreeNova contextual F1 help source (English)

Edit this file to improve runtime help popup text. It is the authored source for contextual `F1` help.

English is the canonical source of meaning and structure for contextual help. Localized variants may improve local wording directly, but any new substantive help content should be added here first so locale files do not diverge in meaning, topic inventory, or link structure.

## Topic-block schema

The top-level `ytnova-help-strip` block owns every popup help-strip label and the Index and Navigation mnemonic keys. The runtime supplies only the actions.

Every topic block in this file follows the same parser-facing contract:

1. The block starts with a level-2 heading in the exact form `## topic:<topic-id>`.
2. The heading is followed immediately by a fenced metadata block labelled `ytnova-help-meta`.
3. The metadata block contains exactly these keys, in this order:
   * `title:` — plain-text topic title.
   * `contexts:` — comma-separated stable runtime context/prompt IDs, or the literal `none` for topics without a direct runtime context.
4. The block then contains exactly one required section: `### Contextual F1`.
5. Links are optional and must answer a distinct, immediate next question. Put a link where its subject arises. Do not add artificial wording merely to accommodate a link. If a necessary link does not fit naturally, end the topic with `See [name](topic:id).` Do not use a separate related-links section.

Authoring rules:

1. Write for the user who pressed `F1` because they need help right now. Use plain language and say what they can do here.
2. Lead with actions. Name the key, say what it does, and say what happens next.
3. When one short line is enough, keep it to one short line. Keep local pages scannable.
4. Explain the parts that are not obvious from the key name alone, especially unusual keys, prompt flows, options, and ytnova-specific syntax or wildcard behavior.
5. Put repeated behavior on one owning page. Local pages should link to that page and explain only the local difference or local use.
6. Keep command rows short, but not cryptic. For prompt-driven or option-heavy commands, say what the user types, what ytnova does with it, and any tagged-file variant before you send them elsewhere.
7. Do not add a link when the visible page can explain the command in one clear line. One-line help belongs where the command is visible.
8. Page titles may end in `Help`. Index entries and topic-link labels should not.
9. When separate keys or actions need explanation, give each one its own short source line. Do not combine distinct key actions merely because they fit in one sentence. A short background thought with no action may use one paragraph.
10. F1 is short contextual help, not the man reference. Keep all useful F1 facts in `### Contextual F1`; do not add a long-form section or manpage-style reference material.
11. Do not replace useful instructions with a vague summary. A user who opens the page must see enough factual guidance to complete the local action or know exactly which related page owns the rest.
12. Backticks are runtime markup, not visible punctuation. Use them for keys, commands, configuration names, and other terms that need the `help_topic` style; do not add literal backticks to the rendered wording.
13. Add a topic link only when its target supplies a distinct, necessary answer. Where it represents an entry key, label it with that visible key and a short action, for example `/ jump` or `F8 split`, rather than the target page title.
14. Use `footer` only for the main program's bottom command rows. Use `help strip` for the popup's lower command row. `Help Index` lists operator topics; the help strip owns the separate `Help Navigation` route. A `link` opens another help page.
15. Before changing a topic, inspect its implementation and live TUI. Check normal and narrow popups for readable wrapping, the correct title, and the correct help-strip wording and colours.
16. Blank source lines deliberately create visual breathing room between help sections. Keep them where they improve scanning; do not collapse them merely to make the source compact.
17. Topic links occur only inside `### Contextual F1`.
18. Order help-strip commands as arrow keys, numeric keys, alphabetic keys, symbol keys, then `Esc/Q`. A topic must not link to itself.

```ytnova-help-strip
left-back-label: Left back
index-label: Index
index-key: I
navigation-label: Navigation
navigation-key: N
follow-label: Enter/Right follow
quit-label: Esc/Q quit
```

## topic:ytnova-navigation

```ytnova-help-meta
title: YtreeNova Navigation
contexts: none
```

### Contextual F1

YtreeNova is built for keyboard use. Mouse effects may occur, but they are incidental rather than designed controls.
Use the `Up` and `Down` arrow keys to move one row at a time.
`Page Up` and `Page Down` move one screen at a time.
`Home` and `End` go to the first and last visible rows.
`Enter` opens the selected item.
`Right` opens or expands the selected item where that view supports it.
`Left` goes back or collapses the selected item where that view supports it.
[/ jump](topic:list-jump) moves to a matching name as you type in the current list. `Enter` selects it; `Esc` cancels.
`Tab` moves to the next visible sibling in the tree and wraps at the end; `Shift-Tab` reverses it.
[F8 split](topic:f8) mode: `Tab` switches active panels; some prompts give `Tab` a local meaning.
[F7 preview](topic:f7) mode: ordinary navigation keys move the file selection; their shifted forms scroll the preview.

`Terminal input limits`
`Alt` is deliberately unsupported because terminals handle it inconsistently.
`Kitty keyboard protocol`
YtreeNova uses the kitty keyboard protocol when the active terminal path supports it. This lets it tell `C-m` from Enter, so `C-m` moves tagged files.
In Kitty, add `keyboard_protocol kitty` to `~/.config/kitty/kitty.conf` and restart Kitty. Other terminals that support the protocol work too.
If you use a multiplexer or remote session, it must pass the protocol through unchanged.
Without protocol support, YtreeNova silently uses `C-n` to move tagged files.
`C-[` is Esc.

## topic:tagged

```ytnova-help-meta
title: Tagged
contexts: none
```

### Contextual F1

Tags select several files, then apply one operation to the group.
Tagged files are indicated by `*` in the margin.

In a file list, press `T` to tag the selected file or `U` to untag it. The selection moves down to the next file.
In a directory tree, `T` and `U` affect files that the current filter allows in the selected directory, then move down to the next directory.

`I` reverses tags on files that the current filter allows in the current scope.

When statistics are shown, tagged-file totals appear there.

Hold the Control key with the letter after `C-` to run the matching operation on all tagged files. `^` in a footer label means the same tagged operation, as in `C/^Copy`.

`C-a` opens the attributes prompt.
`C-c` opens the [copy](topic:copy-move-targets) prompt.
`C-d` asks before deleting tagged files.
`C-m` opens the [move](topic:copy-move-targets) prompt when the protocol is available; without it, use `C-n`.
`C-o` opens the [output](topic:output) prompt.
`C-p` opens the pipe prompt.
`C-r` opens the rename prompt.
`C-s` [searches tagged files](topic:search-tagged) and untags files without a hit.
`C-t` tags all files in the active file list. In a directory tree, it tags files allowed by the current filter in all logged directories.
`C-u` untags all files in the active file list. In a directory tree, it untags files allowed by the current filter in all logged directories.
`C-v` views tagged files one after another.
`C-x` opens a [command prompt](topic:execute-file) and runs the operation once per tagged file.
`C-y` [pathcopies](topic:copy-move-targets) the tagged files.
`C-z` opens the [archive directory](topic:archive-dir) or [archive file](topic:archive-file) prompt, depending on the current selection.

For a tagged-only [filter](topic:filter) scope, press `F`, then `Tab`. This does not change tags.

### Contextual F1

Give ytnova one or more directory or archive paths to log them at startup. With no path, it logs the current directory.

## topic:copy-move-targets

```ytnova-help-meta
title: Copy/Move Targets
contexts: none
```

### Contextual F1

`Copy`, `move`, and `pathcopy` first ask for a name or rename pattern, then for the destination directory.

With one file, leave its autofilled name to keep it, or edit it to rename it. You can use wildcards in either case.

For [Tagged](topic:tagged) files, leave the autofilled `*` to keep their names, or enter a rename pattern:
`*` keeps the remaining original name. Use `copy-*` to add a prefix or `*.bak` to change the extension.
`?` keeps one character from the original name. For example, `??-*` keeps the first two characters, adds `-`, then keeps the rest.
Other characters are used as written.

Use `Up` to reuse a previous name or pattern.

Enter the destination directory in `To Directory`. In [F8 split](topic:f8) mode, it starts as the other panel’s currently selected directory.

Use `Up` to reuse a previous destination, or press [F2](topic:f2-picker) to choose one.

The same prompts apply to [archive files](topic:archive-file) and [archive directories](topic:archive-dir). Copying an archive file extracts it as needed; moving it copies it, then removes the original. You can also copy into a logged archive.

`pathcopy` recreates the selected file’s existing path below the destination directory.

If the destination directory is missing, ytnova asks whether to create it. If a destination file already exists, ytnova asks before replacing it.

## topic:directory

```ytnova-help-meta
title: Directory Help
contexts: main.dir
```

### Contextual F1

This is the `directory window`. It shows the hierarchical directory tree that ytnova has read in the current `volume`.
The selected directory’s files appear in the `small window`.

`+` means ytnova has not yet expanded or logged that directory’s subdirectory branch in the tree.

The `footer` shows the commands available here.
Some commands have their own `F1` help.

`Left` collapses the selected branch. If that branch is already hidden, it moves to the directory above.
`Right` moves into the first shown directory below the selected one. If ytnova has not read the selected directory yet, it reads it first.
`+` reads the selected directory and adds its branch to the tree without moving the selection.
`*` reads every directory below the selected directory without moving the selection.
`-` collapses the selected directory and unlogs its files from the logged tree. They no longer appear in Showall or the statistics.
Press `Enter` to switch into the selected directory’s `file window`. If its tree branch is not logged yet, ytnova reads it first.

The number keys change what you see.
`1` shows names, the default.
`2` shows attributes.
`3` shows the owner.
`4` shows times.
Press an active `2`, `3`, or `4` again to return to names.
These views normally change both this panel’s tree and its `file window`.
Set `SEPARATE_DIR_FILE_VIEWS=1` in `ytnova.conf` to keep them separate.

`5` turns compact names on or off in the `file window`.
`6` switches size units in both tree and file rows.
`7` shows a small text preview for each displayed file.
`8` shows file details for each displayed file.
`9` shows Git information for files in a Git project.
`5`, `7`, `8`, and `9` change only the `file window`.

`Attributes` opens a submenu to alter the selected directory’s attributes.
[Copy](topic:copy-move-targets) copies the selected directory and its contents.
`Delete` deletes the selected directory.
[Filter](topic:filter) changes the files shown in the current view.
`filter-matching` means files allowed by the current Filter.
`Global` shows files from every logged volume in one list.
`I` (`Invert`) reverses tags only on filter-matching visible files in the selected directory.
`J` [compare](topic:compare) compares this directory with another.
`K volume` opens the volume menu.
`Log` reads the selected directory or archive, or reads a logged directory again.
`Makedir` creates a directory below the selected directory.
`Newfile` creates an empty file inside the selected directory.
[Output](topic:output) exports the current selection.
`Pipe` runs a command in the selected directory and sends it the displayed file names.
`Quit` exits ytnova.
`Rename` renames the selected directory.
`Showall` shows all files in the current volume in one list.
`T` and `U` tag and untag all matching files in the selected directory, then move to the next directory.
`C-t` and `C-u` [tag and untag](topic:tagged) all matching files in every logged directory in the current volume.
[moVedir](topic:copy-move-targets) moves the selected directory and its contents.
`eXecute` runs a command for the selected directory.
`Z archive` creates an archive from the current selection.
`/ jump` moves to a displayed name as you type.
`\` shows or hides hidden names.

`F5` refreshes the active view.
`F6` shows or hides statistics.
`F7` turns autoview on or off.
`F8` turns split-screen on or off.
`F9` opens the Applications menu.
`F10` opens configuration.
`Esc` cancels the current operation.

## topic:filter

```ytnova-help-meta
title: Filter Help
contexts: prompt.filter,prompt.filter-tagged
```

### Contextual F1

Type a pattern and press `Enter` to filter the current file list. The prompt starts with `*`, which shows all files.
Use `*.c` for one glob pattern or `*.c,*.h` for either pattern.
Prefix a term with `-` to exclude it, as in `*.c,-test*`.
Use attributes such as `:r` or `:x`, dates such as `>2024-01-01`, and sizes such as `>1M` with the same comma-separated syntax.

When the current scope contains [tagged files](topic:tagged), `Tab` switches the prompt between all files and tagged files without changing any tags.
The filter affects only the current normal, archive, Showall, or Global file list. It is different from [/ jump](topic:list-jump), which only moves the selection.

For a directory, choose the [scope](topic:compare-scope).
Choose the [comparison basis](topic:compare-basis) when more than one is available.
Then choose which [result](topic:compare-results) to tag on the source side.

Logged-tree comparison uses only directories already logged in the tree; it does not open unread `+` branches.
External directory or tree comparison launches `DIRDIFF` or `TREEDIFF` instead of tagging results.
File comparison uses `FILEDIFF`; `%1` and `%2` stand for the two paths, and missing placeholders are appended automatically.
Compare never changes file contents and has no separate tagged-files mode.
